# D3K-1H-C: WIRE CONTRACT LOCK CONFLICT

## Finding

**Crypto Hash Lock Detected**: Field name change breaks all existing profile signatures.

### Current State

Profile struct field (profilebuilder.go:29):
```go
Mapping []FieldMapping `yaml:"mapping_profile" json:"mapping_profile"`
```

Registry digest calculation (registry.go:216-221):
```go
data, err := json.Marshal(p)      // Includes JSON tag: "mapping_profile"
sum := sha256.Sum256(data)         // SHA256 over exact JSON bytes
```

### Breaking Change Impact

**Renaming `mapping_profile` → `mapping_entries`**:

1. JSON bytes change
2. SHA256 digest changes
3. `candidateDigest(candidate)` returns different value
4. Existing signatures fail verification (registry.VerifyAttestation line 153)
5. All locked profiles become invalid

### Locked Interop Test

`TestD3JArtifactMutualConsistency` (governed_handoff_test.go:542-617):
- Builds profile with current schema
- Calls `registry.Admit()` which signs with candidateDigest
- Calls `registry.VerifyAttestation()` which recomputes digest
- **Renaming field breaks this test chain**

### Founder's Gate Condition Met

From DECISION 4:
> "If "mapping" is already cryptographically or interoperability locked and renaming it would break existing signed profiles: STOP and report that exact compatibility conflict."

**This is that conflict.**

## Options

### A) Accept Breaking Change

- Rename `mapping_profile` → `mapping_entries`
- Increment `Attestation.SchemaVersion` from `otris.registry.admission.v1` → `otris.registry.admission.v2`
- Old profiles signed with v1 schema become unmigrable
- Requires deliberate founder approval to break compatibility

### B) Maintain `mapping_profile`, Add New Governance Fields

Keep current tag, add normalization authority as sibling fields:
```go
type Profile struct {
    // ... existing ...
    Mapping []FieldMapping `yaml:"mapping_profile" json:"mapping_profile"` // unchanged
    
    // NEW: normalization authority
    NormalizationAuthority bool   `json:"normalization_authority"`
    NormalizerIdentity     string `json:"normalizer_identity,omitempty"`
    // FieldMapping extended with EvidenceRefs []string internally
}
```

Wire contract then exposes:
```json
{
  "mapping_profile": [...],           // legacy carrier name
  "normalization_authority": true,
  "normalizer_identity": "...",
  ...
}
```

Mutation of new fields still breaks digest (they're in JSON bytes).

### C) Wrapper/Alias Structure (not recommended)

Maintain backward compatibility but complexity grows.

## Recommendation

**Option B** preserves interop lock, adds new governed fields to same JSON, all fields included in digest.

The array carrier name stays "mapping_profile" in JSON but the array elements (FieldMapping) get extended with `EvidenceRefs`.

Edge D3K-1H-B can map profile.mapping_profile → "mapping_entries" in its admission contract if needed, since Edge is currently untouched.

1. Option A (break compatibility + new schema version)
2. Option B (keep current tag, extend with new fields)
